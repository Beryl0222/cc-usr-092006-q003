# 赛事消费归因与清算

城市赛事会联合住宿、餐饮和零售商户发放不同权益。有效窗口可能跨越午夜，退票、改期及商户迟到流水都会影响最终清算，因此原始事件和财务调整需要分开保存。

本模块提供赛事消费归因与清算后端：统一接收票务状态、实名入场、城市权益发放、商户核销、退款和结算事件，在不保存明文身份信息的前提下，把每笔消费归因到具体赛事、活动阶段和合作方案，并产出可复算的账期快照与完整审计链。

## 领域模型

- `data/programs.json` 给出两项脱敏合作方案，时间均携带明确偏移量。每个方案包含：
  - **阶段窗口（phases）**：如预热、赛期、赛后延时（`post_event`），跨午夜窗口据此把流水归入正确场次；
  - **规则版本（rules）**：补贴比例、城市合作伙伴分摊比例（均为基点）、延时消费策略（`keep`/`reverse`）、改期策略（`keep`/`reverse`）。每笔分录都记录规则版本，供审计复算。
- `program.go` 校验方案资料；清算规则由 `engine.go` 执行，对外服务由 `server.go` 承载。

## 事件接入与身份脱敏

`POST /v1/events` 批量接收六类事件（`ticket` / `entry` / `benefit_grant` / `redemption` / `refund` / `settlement`）。每个事件以 `id` 为幂等键：**重复或迟到投递不会产生二次补贴**。

票据与持票人标识在入引擎时即经 HMAC-SHA256 脱敏为伪匿名引用，落盘的原始事件只保留引用，不保存明文身份。

## 归因与冲正规则

- 核销按**业务发生时间**在方案时区下匹配阶段窗口，商户跨午夜上传的流水归入正确场次与阶段；
- 补贴按方案基点比例计算，拆分为城市合作伙伴应收与主办方支出，贷记商户应付款（复式记账，金额以分计）；
- **退款**：部分退款按比例冲正补贴，退清时冲正剩余全部，消除取整尾差；
- **退票 / 取消**：该票在对应场次下已核销的补贴全额冲正，后续核销被拒绝；
- **改期**：按方案规则保留或冲正；改期后原场次权益不可再核销；
- **赛后延时消费**：按方案规则保留，或入账后立即全额冲正（保留审计轨迹）。

## 封账、快照与调整分录

- `POST /v1/periods/{period}/close`（或 `settlement` 事件）封账账期并生成快照：各账户净额 + 覆盖全部分录内容的哈希；
- 封账后到达的迟到事件**不改写已封账账期**，自动转为调整分录落入当前未封账账期；已封账账期只能通过 `POST /v1/adjustments` 的调整分录修正（要求借贷平衡、引用已封账分录）；
- `POST /v1/periods/{period}/verify` 依据当前台账复算，校验与封账快照一致——月末快照可复算到相同金额。

## 数据隔离与审计

调用方角色经请求头声明（`X-Actor-Role` / `X-Actor-Merchant` / `X-Actor-Match`；生产部署时由网关认证后注入）：

- **财务**：全量账簿、封账、快照、调整分录、审计回溯；
- **主办方**：限自有场次的分录与带动消费聚合（`GET /v1/consumption`）；
- **商户**：仅自身应付款行（`GET /v1/ledger`）。

`GET /v1/audit/postings/{id}` 沿原始事件、规则版本和冲正/调整链解释任意一笔应收应付。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/events` | 批量事件接入（幂等） |
| GET | `/v1/ledger?period=` | 按角色隔离的账簿视图 |
| GET | `/v1/consumption?match_id=` | 带动消费聚合（财务/主办方） |
| POST | `/v1/periods/{period}/close` | 封账并生成快照（财务） |
| GET | `/v1/periods/{period}/snapshot` | 查询快照（财务） |
| POST | `/v1/periods/{period}/verify` | 复算比对（财务） |
| POST | `/v1/adjustments` | 封账后调整分录（财务） |
| GET | `/v1/audit/postings/{id}` | 审计回溯（财务） |

## 验收覆盖

`go test ./...` 覆盖：跨日赛程归因、部分退款按比例冲正、并发核销（幂等去重与额度控制）、退票/改期/取消冲正、赛后延时消费双策略、封账后补传生成调整分录、快照复算一致、三方数据隔离、审计链与身份脱敏。
