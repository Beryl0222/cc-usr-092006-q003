# 赛事消费归因与清算

城市赛事联合住宿、餐饮、零售商户发放权益。本服务统一接收票务状态、实名入场、城市权益发放、商户核销、退款与结算事件，在**不保存多余身份信息**的前提下，判定每笔消费归属的赛事、活动阶段与合作方案，并在月末产出可复算的账期快照与可追溯的审计链。

## 设计原则

- **原始事件只追加、不可改**。补贴、冲正、调整都是由事件确定性派生的凭证，全量状态可由事件日志重放重建（事件溯源）。
- **归因与摄入顺序无关**。投影先按业务时间（`occurred_at`）重建事实，再按日志顺序处理封账；迟到、乱序到达的事件产生相同结果。
- **跨午夜按消费时间归属**。商户凌晨上传只影响"迟到宽限"判定，流水归属只看消费时刻落在哪个方案窗口。
- **迟到宽限与封账的优先级**：开放账期内，上传晚于"窗口结束+宽限"直接拒绝；账期已封账时，迟到补传不再丢弃，而是挂起，必须由财务在开放账期用调整分录入账（避免封账后补传无处可去）。
- **封账即冻结**。账期关闭后，任何落在该账期的补贴/冲正都不再自动改写快照，而是挂起（blocked），只能由财务在开放账期登记**借贷平衡且金额精确匹配挂起**的调整分录承接。
- **金额用整数最小单位（分）**，补贴按基点（bps）与单笔封顶计算，冲正按剩余比例连乘：`S − S·(1−rM/A)·(1−rT/F)`。
- **最小化身份数据**。只保存票号、权益发放号这类假名标识；载荷出现姓名、证件号、手机号等字段一律拒绝（HTTP 422）。

## 目录

```

engine.go    事件投影、归因、冲正、封账冻结、调整、汇总、快照哈希链、审计链、范围隔离

```

## 事件模型（`POST /v1/events`）

信封：`{event_id, type, occurred_at, received_at?, payload}`。`received_at` 缺省时平台事件取业务时间，商户事件取服务端时间。

| type | 含义 | 关键规则 |
|---|---|---|
| `ticket.issued` / `ticket.refunded` | 发票 / 退票（增量，可多次部分退） | 消费前全额退→核销拒绝；部分退→补贴按未退比例缩放；消费后退→按比例冲正 |
| `ticket.rescheduled` | 票改签到其他场次 | 改期后旧场次权益不可用；改期前消费保留 |
| `match.rescheduled` / `match.cancelled` | 赛事改期 / 取消 | 已发生消费改期保留；取消冲正至全额 |
| `access.verified` | 实名入场 | 要求入场的方案须在宽限内匹配票号+赛事 |
| `benefit.granted` / `benefit.revoked` | 权益发放 / 作废 | `single_use` 权益并发核销只成一笔（业务时间+核销ID决胜） |
| `redemption.recorded` | 商户核销流水 | 窗口/货币/权益/入场/单次/退票/取消校验，输出赛事+阶段+补贴 |
| `redemption.refunded` | 商户侧退款 | 与退票冲正按剩余比例连乘，不重复扣减 |

封账与调整**不能**走通用事件入口，必须用专用命令。

## 账期、快照与调整

- `POST /v1/periods/{period}/close`（仅 finance）：重算当期凭证数与各维度合计，写入带 SHA-256 哈希链的快照事件。
- `GET  /v1/periods/{period}/verify`（finance/platform）：从事件日志重新推导金额、凭证数与哈希，与快照逐项比对。
- `POST /v1/adjustments`（仅 finance）：调整分录，借贷必须平衡；引用 `origin_event_id` 时金额必须与挂起影响**分毫不差**，目标账期必须是开放账期。
- `GET  /v1/blocked`：查看封账后挂起、等待调整的业务影响。

## 角色与数据隔离

鉴权头：`Authorization: Bearer <token>`，约定 `platform` / `finance` / `organizer:<id>` / `merchant:<id>`（生产应替换为令牌表/网关鉴权）。

- **platform**：全部读，可投递各类平台事件。
- **finance**：封账、调整、复算、全部审计；不直接投递业务事件。
- **organizer:<id>**：仅本主办方应收与自有赛事/方案/阶段维度；看不到商户身份（响应中商户字段被抹除），不能封账。
- **merchant:<id>**：仅本门店流水与应付；只能上报本门店核销/退款，看不到主办方维度。

## 运行与验收

```bash
go run ./cmd/server                 # 默认 :8080，可用 ADDR 覆盖
go test ./...                      # 单元 + HTTP 验收
go test -race ./...               # 并发互斥竞态检测
go vet ./...
```

验收用例覆盖：

1. **跨日赛程 / 跨午夜上传**——00:30 消费、04:30 上传仍归 0920 场次的赛后阶段；窗口外流水拒绝。
2. **部分退款**——两次退票累计 50%，补贴分两步冲到净额 50%；同业务键重复退票不二次冲正。
3. **并发核销**——并发请求下同一张单次权益只成一笔，决胜与到达顺序无关。
4. **封账后补传**——9 月账关闭后补传挂起、快照不变，只能在 10 月以金额精确的调整分录承接；另覆盖封账后退票冲正。
5. 另含改期保留、赛后延时保留、赛事取消全额冲正、顺序无关性、幂等重发、角色隔离、夹带身份字段拒绝、快照复算与审计链完整性。

## 说明

当前实现为**单进程内存账本**，事件日志即事实来源；生产化时应把只追加事件日志落到持久存储（同一套 `project()/replay()` 可直接重放），并把 Bearer 约定替换为正式鉴权。
